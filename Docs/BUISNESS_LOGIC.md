# Business Rules

## UserRole — вычисление роли

Роль не хранится в БД, вычисляется динамически:

| Условие | Роль |
|---------|------|
| `department_id = 1` (тех отдел, захардкожен) | `Admin` |
| `departments.head_id = userId` (любой отдел) | `Head` |
| Иначе | `User` |

**Приоритет**: если пользователь одновременно в тех отделе и является руководителем — роль `Admin` (уточнить поведение, TODO).

**Admin может**:
- Доступ к `/api/admin` — CRUD пользователей, бан/разбан
- Редактировать любой отдел через админ-панель
- **Исключение**: тех отдел (`id = 1`) — Admin не может менять его состав и руководителя (защита от самоудаления)

**Забаненный пользователь**:
- Не может войти в систему (блокировка на уровне auth)
- Не видит чаты, не может читать и писать

## Права в чатах

> Применяется только к чатам типа `Group`. Для `Contact` и `Department` — отдельные правила ниже.

| Действие | Member | Admin | Owner |
|----------|--------|-------|-------|
| Читать сообщения | ✅ | ✅ | ✅ |
| Отправить сообщение | ✅ | ✅ | ✅ |
| Добавить участника | ✅ | ✅ | ✅ |
| Удалить участника | ❌ | ✅ | ✅ |
| Изменить роль участника | ❌ | ❌ | ✅ |
| Редактировать название/аватар | ❌ | ❌ | ✅ |
| Удалить чат | ❌ | ❌ | ✅ |
| Покинуть чат | ✅ | ✅ | ❌ |

> Owner не может покинуть чат — сначала должен передать роль Owner другому участнику.
> Owner не может быть удалён из чата другими участниками.

## Contact-чаты (личные диалоги)

- Создаются автоматически при первом обращении пользователя к другому пользователю
- Системные сообщения **не создаются** для Contact-чатов
- Roles (Member/Admin/Owner) не применяются — чат всегда между двумя участниками
- Можно удалить (soft delete или физически — уточнить)
- Уведомления mute/unmute работают как обычно

---

## Department-чаты

- Создаются автоматически при создании отдела
- Удаляются при удалении отдела
- Состав участников синхронизируется **через триггеры в БД**:
  - Сотрудник добавлен в отдел → автоматически добавляется в чат отдела
  - Сотрудник удалён из отдела → автоматически удаляется из чата
- Ручное добавление/удаление участников через сервисы **не требуется** — управляется триггерами
- Системные сообщения применяются (в отличие от Contact)
- Управление чатом (название, аватар) — через отдел, не напрямую

> ⚠️ Агент не должен реализовывать синхронизацию участников Department-чата на уровне сервисов — это делают триггеры БД.

## Сообщения

### Редактирование
- Только автор сообщения
- Без ограничения по времени
- После редактирования: `edited_at` обновляется, `is_edited = true` в DTO

### Удаление
- Автор сообщения
- Admin или Owner чата
- Реализовано как **soft delete** (`is_deleted = true`)
- Содержимое не возвращается клиентам после удаления

### Системные сообщения
- Создаются автоматически сервисом `SystemMessageService`
- Только для `Group` и `Department` чатов, **не для Contact**
- События: `MemberAdded`, `MemberRemoved`, `MemberLeft`, `RoleChanged`, `ChatCreated`
- Не могут быть отредактированы или удалены пользователями

## Опросы

| Действие | Условие |
|----------|---------|
| Проголосовать | Чат не закрыт (`closes_at` не истёк) |
| Изменить голос | Разрешено (повторное голосование перезаписывает) |
| Закрыть досрочно | Автор опроса или Admin/Owner чата |
| Голосовать после `closes_at` | ❌ Запрещено |

## Общие правила

### Soft Delete
- Сообщения удаляются через `is_deleted = true`
- Физически из БД не удаляются
- Клиент не получает содержимое удалённых сообщений

### Уведомления
- Mention (`@username`) генерирует отдельное уведомление типа `mention`
- Если чат замьючен — push не показывается, счётчик всё равно растёт
- Если чат открыт — popup не показывается, только unread-счётчик

### Пагинация
- Максимальный размер страницы: 100 (нормализуется в `BaseService.NormalizePagination`)
- Default pageSize: зависит от эндпоинта (15 для основной пагинации, 30 для before/after, 50 для around)
