# Нагрузочные тесты API

## Голосовые звонки

Проект `API.LoadTests` содержит консольный нагрузочный сценарий для серверного relay голосовых звонков.
Сценарий поднимает in-process `CallRelayService`, создаёт групповые звонки через `ICallSessionService`, подключает виртуальных участников и отправляет UDP Opus-фреймы на relay. Каждый виртуальный участник также слушает mixed-аудио, которое возвращает `CallMixerService`.

Базовый запуск:

```bash
dotnet run --project API.LoadTests -- --calls 20 --participants 6 --duration 30 --fps 50
```

Более тяжёлый профиль:

```bash
dotnet run --project API.LoadTests -- --calls 50 --participants 8 --duration 120 --fps 50 --min-receive-ratio 0.60
```

Основные параметры:

- `--calls` — количество одновременных групповых звонков;
- `--participants` — количество виртуальных участников в каждом звонке;
- `--duration` — длительность активной фазы теста в секундах;
- `--fps` — частота отправки Opus-фреймов каждым участником;
- `--ramp-up` — плавный запуск участников в секундах;
- `--relay-host` и `--relay-port` — адрес UDP relay; по умолчанию `--relay-port 0`, поэтому тест автоматически выбирает свободный локальный порт и не конфликтует с уже запущенным API;
- `--min-receive-ratio` — минимальная доля полученных mixed-пакетов относительно ожидаемых;
- `--verbose` — информационные логи сервисов звонков.

Тест завершается с кодом `0`, если все звонки и участники созданы без ошибок, нет ошибок UDP-отправки, а `Receive ratio` не ниже заданного порога. Код `2` означает, что нагрузочный критерий не выполнен.
